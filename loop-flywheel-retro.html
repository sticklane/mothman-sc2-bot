5. Workflow Changes Applied

  1. Run 2-Minute Head-to-Head Check Before the 30-Minute Roster
    • Impact: Saves 446 min across Loops 34–88 (15.9 min/release); catches regressions in 2 min instead of 31 min.
    • Check: H2H runs first; stops early if H2H finishes ≤ 3–3 or any race goes 0–2.
  2. Brain and Runtime Production-Cap Contract Check (<3s in Gate 1)
    • Impact: Prevents split-brain held builds and lifts Gate-2 release rate 30.1% → 58.3%.
    • Check: Gate 1 asserts runtime production caps ≥ brain caps and Colossus > Phoenix > Stalker.
  3. 25-Second Targeted Drill Pre-Check for Repeatedly Edited Rules
    • Impact: Flags 11 repeatedly edited rules before changes land; saves 74 min in wasted full drill runs.
    • Check: Any rule touched in ≥ 2 of the last 3 runs requires a 25-second targeted drill A/B pass before the full benchmark.
  4. Pre-Assigned Test Ownership and Fast Unit-Test Mode
    • Impact: Removes ownership wait pauses (12 min) and CPU-contention timing retries (706 min across Loops 34–88).
    • Check: Authors edit their own track tests directly; the verifier owns wall-clock timing checks on an idle CPU.
  5. Post-Run Log Review, Trade Video Contact Sheets & Quiet Polling
    • Impact: Updates timing logs in <3s after each run, pairs worst fights with 6-frame video sheets, and cuts idle monitor polling (watchdog polling previously logged 20,446 steps for 8 alerts).
    • Check: Each run appends to the run timing log and produces replay and video trade review packs.

6d. Key Bottleneck Findings and Fixes

  1. Benchmark concurrency: Earlier runs used 10 of 32 threads (31.2% utilization). Both 18-match 3-race canaries and full 84-match runs now target 12 concurrent workers to avoid CPU-contention timeouts.
  2. Match scheduling: Five earlier runs launched matches in fixed order. Longest-first (LPT) scheduling is now enabled by default so slow opponents start in Wave 1 and cut tail wait to 7.9% in L65H, 2.9% in L66, and 1.7% in L67B.
  3. Drill runner model tier: The combat drill runner spent extra reasoning time (1866 s, 81.1% of active time); switching mechanical runners to a lighter tier reduces command turnaround latency.
  4. Post-match handoffs: Multi-turn serial post-benchmark steps (up to 12 turns in earlier runs) were collapsed into a single parallel post-benchmark pipeline.
  5. Ad-hoc replay scripts: Repeated 60 to 90 s inline replay analysis scripts are being replaced by cached reusable diff tools.
  6. Scoped lane tests: One scoped lane test pass took 33.0 s in L80B; keeping per-lane bytecode caches warm avoids cold recompilation.
  7. Serial post-match scripts: Serial scoring and replay extraction took 56 to 61 s per run; the parallel pipeline now completes the full pass in 29.0 s.
  8. Full test suite: 5 author runs of the full test suite exceeded 30 s (max 35.0 s); authors now run targeted lane tests while the verifier runs the full suite once per pass.
  9. Full-tree builds: Full bytecode rebuilds took 33 s; scoped lane test runners compile only edited modules and target tests.
  10. Uncompiled test runs: Source-only Racket test runs reached 43 s; isolated per-lane bytecode caches eliminate repeated cold compilation.
  11. Short-gate tail wait: 7 short canary or head-to-head runs spent over 25% of wall time waiting on the slowest match (worst 48.4% in L65F); longest-first ordering prioritizes historically long pairings first.
  12. Replay forensics diffs: One replay diff pass took 37.0 s in L67B; caching per-match features keeps future diffs under 10 s.
  13. High-command sessions: 11 roles exceeded 15 shell commands in a single loop session (peak 96 commands by Coordinator in L48); reusable scoring and diff tools replace those manual loops.
